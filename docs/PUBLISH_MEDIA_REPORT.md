# FLOWFRAME 发布媒体报告

更新日期：2026-09-11

## 最终压缩目标

完整视频以代表性运动窗 SSIM 约 0.95 为压缩目标；15 个背景预览独立以约 0.97 为目标。两类媒体不共用压缩参数。按用户要求，最后一轮只进行编码和必要的数值、格式核对，不生成截图，不做图片检查，不进行全片 SSIM 扫描。

5 部完整视频均由各自的 4K 原片生成，保留全部时长和原帧率，输出 1920×1080、H.264 High、yuv420p、AAC 128 kb/s 双声道、faststart。源文件保留。完整视频总体积由约 911.5 MiB 降至 98.9 MiB，减少约 89.1%。

## 背景与封面

背景的 15 个预览片段仍保持原裁切比例、分辨率、帧率和 6–7 秒时长，且没有音轨。它们仅供详情页背景循环，完整播放页不会使用这些片段。独立参数由 `FLOWFRAME_PREVIEW_CRF` 控制，默认28，与完整视频的 `FLOWFRAME_VIDEO_CRF` 分开。15 段相对预览母版的数值 SSIM 范围为0.967568–0.995065；最低运动样本约0.97，静态片段保留更高分数，不继续追求极限压缩。

15 个背景预览合计11.63 MiB。9 张 WebP 封面使用 quality 84，尺寸不变，总体积从 1.74 MiB 降到 1.10 MiB，减少 36.9%。原有约 65 KiB 的 JPEG 详情图和旧配置使用的小型占位视频保留。

## 重建与发布

`pnpm prepare:publish-media` 从 4K 原视频、高质量预览母版和封面母版生成发布文件。完整视频默认分别使用 CRF32、30、38、43、40；预览使用独立档位。不会把上次发布输出再次作为有损编码输入。

`pnpm verify:media` 检查格式、分辨率、帧率、完整时长、音轨和 faststart。`pnpm update:media-manifest` 更新发布素材清单。先更新 Sites 媒体来源，再同步 GitHub Pages。

浏览器 IndexedDB 上传仍用于本地预览和配置，不会自动执行 ffmpeg；正式发布前需提供可追溯源文件并执行压缩流程。
